# ESPEC — oráculo da feature harness-evolucao

Fonte: `.claude/state/features/harness-evolucao/FEATURE.md` (CA-01..CA-19, "Decisões travadas na E1", edge cases).
Arquivos: `_alvo.py` (alvo de rascunho + CLI real), `test_harness_evolucao.py` (um `TestCA<NN>` por CA). Quem
implementa NÃO edita esta pasta; mudança só por mudança oficial (`campanha.py mudanca-oficial` com PORQUE).

Rodar (da raiz do projeto): `python -m unittest discover -s campanhas/harness-evolucao/oraculo -p "test_*.py" -k CA01`
(CA01..CA19; sem `-k` roda tudo). Cada classe tem testes reais (exit, saída, arquivo gravado, evento) e um
`test_calibracao_*` (o verificador reprova o resultado vazio/errado e aprova um resultado bom conhecido).

## Ambiente e alvo

- Skill testada: `$CS_DEV_SKILL_DIR` (padrão: a raiz do projeto). Todo script vem de lá.
- Alvo: `scripts/harness/tests/fixture.py:make_repo(with_state=False)` da skill (repo git em tempfile; team com 5
  agentes: dev-billing `src/billing/**`, dev-users `src/users/**`, po `docs/stories/**`, reviewer e security de gate;
  invariante escopada `rule.billing.cents` em `src/billing/**`; `rule.global.utf8` em `**` é GLOBAL, não escopada)
  + `accept/test_nunca.py` (sempre vermelho) e `accept/test_marca.py` (verde só se `$CS_ORACULO_MARCA` existe),
  commitados. Harness por `cs.py --target <alvo> harness install --platforms claude-code --allow-outside --no-settings`.
- CLI: `cs-state` = `<alvo>/.swarm/harness/state.py --root <alvo>`, `cs-mem` = `<alvo>/.swarm/harness/mem.py --root
  <alvo>`, guard = `<alvo>/.swarm/harness/guard.py <modo>` (payload no stdin, `CLAUDE_PROJECT_DIR`). É o que os
  wrappers `.swarm/bin/cs-*` executam; o oráculo chama o .py com `sys.executable` porque o wrapper chama `python3`.
- Comandos de verify/aceite usam o interpretador do teste por caminho absoluto entre aspas (`"<py>" -m unittest …`),
  nunca `python3`. Critério das tasks: `AC-1|Dado … Então …|` (sem test-id: o runner de test-id do config usa
  `python3`). Toda task leva `--criterio` (inclusive CHORE) e `--verify-cmd`.
- Pipeline M2 de uma task (sem atalho): `start` → `dispatch --manual --model <route.model do item>` → `submit` (ator =
  agente) → `verify` → `review --by reviewer --verdict PASS --findings …` → `accept` → `close` só se o item ainda não
  estiver em `archive/` (CA-12: a propagação fecha os pais).
- Eventos: procurados em `.swarm/events.jsonl` (cadeia do motor), `.swarm/harness-ledger.jsonl`, `.swarm/ledger.jsonl`
  (e os mesmos em `.swarm/state/`). Um registro "é" o evento `X` se `type|kind|event|acao|action|op|name` == `X` ou
  termina em `.X`/`:X`; os campos de `data` são lidos junto com os do registro.
- Leitura de item: caminho vindo de `cs-state tree --json` (`zonas.{backlog,state,archive}`), arquivo lido como JSON
  estrito ou, se falhar, JSON5 (leitor do motor). Memória do agente: `.swarm/state/memory/agents/<n>.json` (ou
  `.json5` legado; também aceito em `.swarm/memory/agents/`).
