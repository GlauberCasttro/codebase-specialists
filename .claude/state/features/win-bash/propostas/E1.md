# E1 — Análise da demanda

Demanda (literal): "sim" — à proposta A: "uma mini-feature `win-bash` antes: só o `.claude/tools/feature.py` (+ o
teste dele) — no Windows, a chamada do `conferir-commit.sh` passa a usar o bash do Git, nunca o `System32\bash.exe`
do WSL".

Problema por trás: nesta máquina Windows nenhuma feature consegue fechar. `feature.py:548` roda
`subprocess.run(["bash", <conferir-commit.sh>, …])`; no Windows o Python 3.12 resolve o nome `bash` pela busca do
CreateProcess, que acha `C:\Windows\System32\bash.exe` (o WSL) antes do PATH — e o bash do WSL não entende o caminho
`C:\…` (`/bin/bash: C:Users…conferir-commit.sh: No such file or directory`). O `conferir-commit.sh` passa quando
rodado pelo Git Bash (6 arquivos idênticos ao portão VERDE da win-motor-copia), mas `fechar check`, `fechar archive` e
`fechar commit` dependem dessa chamada: a win-motor-copia está aceita e parada no gate por isso.

O que NÃO é: não é o resto do harness no Windows (`python3`/`/usr/bin/python3` fixos, régua, `.gitattributes`
inteiro, as 13 chamadas `["bash"…]`/`["sh"…]` nas suítes de teste do harness — B-15); não muda o comportamento no
macOS/Linux (lá `bash` continua o mesmo); não toca `conferir-commit.sh` nem os outros tools.

Perguntas abertas (máx. 3, só as que mudam o desenho):
1. Como escolher o bash no Windows?
   → recomendo: `shutil.which("bash")`, descartando um resultado dentro de `%SystemRoot%\System32` (o WSL); se não
     sobrar nenhum, procurar o `bash.exe` do Git a partir de `shutil.which("git")` (raiz da instalação, `bin\bash.exe`
     ou `usr\bin\bash.exe`); sem nenhum, recusar com mensagem clara — nunca cair no WSL em silêncio. Medido:
     `shutil.which("bash")` = `C:\Program Files\Git\usr\bin\bash.EXE` no Git Bash e no PowerShell, enquanto
     `subprocess.run(["bash", …])` cai no WSL (rc 2).
     alternativa: variável de ambiente `CS_DEV_BASH` obrigatória no Windows (mais simples, exige configurar).
2. Onde fica a função?
   → recomendo: em `feature.py` (escopo de 1 arquivo de código, sem colidir com a win-motor-copia); a B-15 a move para
     `estado_lib.py` quando corrigir o harness inteiro.
     alternativa: já em `estado_lib.py` (2 arquivos; reaproveitável agora, escopo maior).
